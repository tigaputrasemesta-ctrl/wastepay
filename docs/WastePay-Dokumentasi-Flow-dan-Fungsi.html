1. Ringkasan Sistem

WastePay (brand: O₂W Hero Zero Waste) adalah platform terpadu untuk pengelolaan iuran kebersihan dan operasional pengangkutan sampah skala kelurahan/kota. Sistem menggabungkan tiga portal dalam satu aplikasi:

PortalPenggunaFungsi Utama
Web AdminSuperadmin, Admin, KasirManajemen pelanggan, wilayah, zona, tarif, tagihan, pembayaran, pengangkutan, petugas, keuangan, laporan, pengaturan.
Mobile PetugasPetugas Lapangan (angkut / tagih / survei)Survei calon pelanggan, lapor pengangkutan via kode, absensi, klaim dana, chat, GPS lokasi.
Portal WargaPelanggan / wargaPendaftaran mandiri, cek & bayar tagihan, lacak status, pengaduan, lihat tarif.

Sistem ini mencatat siklus hidup penuh pelanggan: dari pendaftaran → survei → aktivasi → penagihan bulanan → pembayaran (tunai/transfer/gateway) → pengangkutan terjadwal → pelaporan & rekonsiliasi keuangan. Seluruh perubahan data dicatat pada Audit Log untuk keperluan akuntabilitas.

3. Aktor & Hak Akses (RBAC)

Hirarki peran diatur di src/lib/rbac.ts (nilai level). Semakin tinggi level, semakin luas aksesnya.

PeranLevelDeskripsi & Kewenangan
Superadmin100Akses penuh termasuk manajemen pengguna & audit log.
Admin50Operasional penuh: pelanggan, tagihan, pembayaran, pengangkutan, petugas, zona, laporan. Tidak bisa kelola pengguna/audit.
Kasir20Terbatas: dashboard, peta, tagihan, laporan, notifikasi.
Petugas Lapangan10Mobile: peta, survei, pengangkutan, tagihan (tagih), jadwal, komplain, absensi, klaim. Jabatan: angkut, tagih, survei.
Warga / Pelanggan—Portal publik: daftar, bayar, lacak, pengaduan.
Scope approval (terbaru): untuk sementara (1 perusahaan) semua petugas dapat mengakses & menyetujui semua kelurahan — dikendalikan flag PETUGAS_SCOPE_ALL = true di src/lib/scope.ts. Pembatasan jabatan (survei/tagih/angkut) tetap berlaku. Bila ingin membatasi per kelurahan, ubah flag menjadi false.

Ada dua jalur pendaftaran: (a) mandiri oleh warga via portal publik, dan (b) manual oleh admin via menu "Daftar Baru". Data pelanggan menyimpan kategori, alamat, koordinat (dari foto EXIF/GPS perangkat/manual), penanggung jawab, dan referal.

5.2 Tarif, Paket & Kode Pelanggan

  • Kategori Tarif: rumah tangga, bisnis, kost, sekolah, rumah makan, perkantoran, industri, lainnya — masing-masing punya tarif default.
  • Paket: nama paket + harga (mis. "2x seminggu"), bisa dioverride dengan custom tarif per pelanggan.
  • Kode Pelanggan di-generate otomatis dari kode wilayah, dipakai sebagai identitas barcode & pencarian lapor.

Tagihan bersifat idempotent (satu pelanggan satu tagihan per bulan/tahun). Rincian pembayaran = jumlah + PPN 11% + denda (jika ada).

5.4 Pembayaran & Verifikasi

MetodeAlurVerifikasi
TunaiPetugas tagih / kasir catat → langsung lunas.Otomatis (dicatat oleh yang menerima).
Transfer / e-wallet / QRIS / VAPelanggan unggah bukti → status pending.Admin verifikasi manual (terima/tolak).

Setiap pembayaran tercatat atribusinya (verifiedById) untuk rekonsiliasi kas harian.

5.5 Tunggakan & Denda

Tagihan yang lewat jatuh tempo otomatis ditandai tunggakan dan dihitung denda 2% per bulan keterlambatan. Proses utama berjalan via cron scripts/reminder-wa.mjs; pemanggilan dari GET hanyalah fallback dengan throttle 5 menit untuk mencegah write berlebihan.

5.8 Keuangan: Pengeluaran, Klaim, Rekonsiliasi, Laporan

  • Pengeluaran: catat BBM, gaji petugas, perawatan, operasional (dengan bukti).
  • Klaim Dana Petugas: petugas ajukan klaim (BBM/perawatan/dll) → admin setujui/tolak.
  • Rekonsiliasi: bandingkan total pemasukan, pengeluaran, tunai sistem vs tunai fisik → hitung selisih.
  • Laporan: ringkasan pemasukan/pengeluaran/tunggakan, ekspor data.

5.9 Komunikasi: Pengumuman, Notifikasi WA, Chat

  • Pengumuman: broadcast (semua atau per wilayah) → tampil di landing & kirim WA.
  • Notifikasi: antrean WA otomatis (tagihan jatuh tempo, jadwal, komplain, pengumuman) dengan status terkirim/gagal.
  • Chat Petugas: percakapan dua arah admin ↔ petugas lapangan.

10. Keamanan & Proteksi Data

AspekImplementasi
AutentikasiSesi JWT; tokenVersion dinaikkan saat ganti/reset password → semua sesi lama otomatis dicabut (revoke).
Otorisasi (RBAC)Cek peran via hasRole() + menu dinamis getAllowedMenus(); guard server di tiap route.
Scope data petugasPembatasan geografis via src/lib/scope.ts (saat ini dibuka untuk semua kelurahan, siap dibatasi per kelurahan/zona).
Anti-enumerasiEndpoint detail mengembalikan 404 (bukan 403) bila resource di luar scope; nomor telepon di-mask di halaman publik.
Rate limitingsrc/lib/rate-limit.ts membatasi percobaan pada endpoint sensitif.
CSRFProteksi CSRF via src/lib/csrf.ts untuk mutasi state.
Integritas pembayaranCallback Duitku diverifikasi HMAC-SHA256; status tidak pernah di-update dari redirect (anti-manipulasi).
Soft deletePelanggan, tagihan, petugas, kendaraan, zona dihapus lunak (deletedAt) agar data tetap bisa diaudit.
Audit trailSetiap create/update/delete dicatat di AuditLog dengan data sebelum/sesudah dan atribusi user.
Atribusi anti-spoofingID petugas/pembuat diambil dari sesi server, bukan dari body request.
